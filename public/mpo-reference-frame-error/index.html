Image input validation · technical comparison

Why one reference image failed and the other worked

The failed upload was a two-frame MPO file disguised by a .jpg extension. The successful reference was a single-frame WebP, matching the API’s one-frame requirement.

Finding

The failure occurred during reference-image validation, before image generation. The backend explicitly returned reference image must contain exactly one frame. Direct inspection confirmed two frames in the earlier file and one frame in the successful file.

Technical breakdown

1 · Extension is not the file format

The old asset ended in .jpg, but its contents decoded as MPO. MPO can store multiple images in one file.

2 · Input check rejected the extra frame

The endpoint requires exactly one frame. The two-frame reference failed that check, producing the logged error before generation.

3 · Single-frame input passed

The new WebP decoded to one frame; the same API and 1024 × 1024 output setting then completed successfully.

Evidence limit: This is a strong match to the logged frame-count error, but not a perfectly controlled test: the reference image and prompt changed between runs. Use a standard single-frame JPEG or PNG/WebP export for the earlier image and retry to isolate the variable.

Source: the two supplied job logs and direct inspection of both reference-image files.
